**P06** — Vietnam is drawn in `lead_finding` red. The skill reserves red for stark

**P11** — the run's best analysis (decade-average investment vs next-decade growth,

clarifying sentence in the skill rather than a scold.

## Patterns across the run (what should change)

1. **`highlight_sz` creep — the most common deviation (P02, P04, P08, P12).**
   Single-series and coequal multi-series lines are routinely drawn at the 2.4px
   focus width; the spec reserves it for a focus *over a muted backdrop* (standard is
   2px, the bare-geom default). Cause is visible in the skill text: the mute-then-paint
   example pairs `color = highlight` with `linewidth = highlight_sz`, and sessions
   copy the pair even with no backdrop present. **Fix (skill text):** one line under
   rule 12 — "no muted layer in the chart → no `highlight_sz`; a lone or coequal line
   is `color = highlight` at the default width." A lint heuristic (flag `highlight_sz`
   in scripts with no second line layer) is possible but text may be enough.

2. **The "standalone chart" gap — sessions keep reaching for a mode that doesn't
   exist.** Asked for a bare PNG, sessions split: P04/P11/P12 chose slide mode
   ("standalone chart — carries its own title/source"), the rest stayed in report
   mode, which yields PNGs with **no title and no source anywhere** (P01–P03,
   P05–P07, P09, P10, P13, P14) — the checklist calls that incomplete. The probe run
   even invented `gl_setup(mode = "standalone")`, which `theme_gl()` silently
   half-accepted. **Fix (two rungs):** (a) `match.arg(mode, c("report","slide"))` in
   `gl_setup()`/`theme_gl()` so invented modes error; (b) a skill rule: "chart not
   destined for a GL document → slide mode, so title + source render in-chart;
   report mode is only for figures a document will caption."

3. **Zero-baseline blind spot is narrow, not broad.** Applied correctly 5 of 6 times
   it was warranted; the one miss (P01) is where negative values are rare in frame.
   Watch, don't re-architect.

4. **Scripts aren't always self-contained.** P06, P11, P12, P14 read intermediate
   CSVs; P11's construction lives only in the transcript (P14 at least left its .sql
   files). Not a design violation, but the .R alone can't reproduce the chart.
   **Fix (skill text, one line):** "write the full pipeline — raw file → chart —
   into the script."

5. **Named sector palettes don't trigger on their own (P14).** The session built
   custom sector groups + categorical palette rather than `scale_fill_gl("hs_sectors")`
   for Atlas data. Defensible chart, missed house convention. P15/P16 (stopped) were
   the other two tests of this — worth running before deciding anything.

6. **What's working and should be left alone:** the paint-once highlight (P05, P07,
   P12 — zero muddy-dot violations, the thing v2.1 was written to kill), dark-tone
   discipline for every label tied to a mark (perfect across all 14), mute-then-paint
   on bars/boxes/lines, gridline flips on horizontal bars, `labs(x = NULL)` on year
   axes, save-size selection, and slide-mode title periods (P04, P11, P12 all correct
   — the probe's miss did not recur).

## Addendum — human review of the figures (same day)

Taimur reviewed the rendered charts and raised five observations; each was
verified against the theme code and the rendered pixels. Two turned out to be
**system bugs** — the sessions were compliant; the theme was not. This is a pass
the machine audit missed: it checked the scripts against the rules but not the
rendered geometry against typographic standards. Worth folding into the
chart-audit checklist.

1. **P03/P09 — y-axis country labels ragged (not right-aligned).** Confirmed,
   and not the sessions' fault: `theme_gl()` builds with
   `theme_minimal() %+replace% theme(...)`, and `%+replace%` swaps elements
   wholesale — specifying `axis.text.y = element_text(margin = ...)` silently
   dropped theme_minimal's `hjust = 1`. Every y-axis label in every chart was
   ragged. **Fixed in `theme_gl.R`** (`hjust = 1` restored on `axis.text.y`,
   `vjust = 1` on `axis.text.x`), alignment rule added to `grammar.md` §3.5,
   playground re-rendered to verify.
2. **P04 — "line color vs darker label" rule not visible.** Verified compliant
   by pixel-sampling the label region: each label is drawn in its series' dark
   tone (dark-tone pixels outnumber main-tone ~2.5:1 there; the main-tone pixels
   are the line ends). The dark/main contrast is simply subtle at 12px — a spec
   property (Nil's tone pairs), not a bug.
3. **P05 — label size, and halo request.** Size is per spec: the label is
   `gl_text_size` = 9pt, identical to the axis text (Nil §3 sets *all* chart
   text at 12px). The halo suggestion was adopted as a system convention:
   `grammar.md` §3.5 now specifies a thin `paper` halo on any text drawn over
   data, `gl_endlabel()` applies `bg.color = gl$paper, bg.r = 0.1` by default,
   and the skill's highlight example + guidance tell sessions to pass the same
   to explicit `geom_text_repel` layers.
4. **P06 — Vietnam in red.** Confirmed (was already FLAG). The skill now states
   the principle explicitly: *red signals valence, not emphasis strength* — a
   focus-vs-peers chart is the default-blue case.
5. **P09 — same alignment issue as P03.** Same root cause, same fix (1).

System changes from this review: `theme_gl.R` (axis-text justification,
`gl_endlabel` halo), `grammar.md` (§3.5 alignment + halo conventions),
`SKILL.md` (halo guidance, red-valence rule), playground re-rendered clean.
The P01–P14 figures in this run predate the fixes and keep the old rendering.
